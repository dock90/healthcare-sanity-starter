# Decisions

Decisions the spec left open, made once here so nobody has to re-make them. Newest at the bottom. Each entry: what, why, and what it rules out.

## Stack versions
- **Next.js 16.3 (App Router), Sanity 6.10, Tailwind 4, React 19.** The prompt said "Sanity v5"; v6 is the current stable and `next-sanity` 13 targets both. No reason to start a fresh repo on a previous major. `sanity.config.ts` carries `"use client"` because Sanity 6's package graph is client-only and the Studio route is a Server Component by default.
- **`@sanity/client` pinned to ^7.26** to match `next-sanity`'s peer range and avoid two copies in the bundle.
- **npm, not pnpm/bun.** Lowest-friction for `npx create-next-app -e`.

## Repo layout
- No `src/` directory (per build prompt). Studio lives at `app/studio/[[...tool]]`.
- `AGENTS.md` is generated by `next dev` and committed so the tree stays clean; it's not a project doc.

## Environment
- One `.env.example` with every variable documented inline. Dev works with only the three `NEXT_PUBLIC_SANITY_*` values because the demo dataset is public-read.
- Turnstile test keys are committed in `.env.example`. They are Cloudflare's published always-pass keys, not secrets.

## Known transitive audit items
- `npm audit` reports a `js-yaml` advisory via `sanity → @vercel/frameworks` and `uuid` via `typeid-js`. Both are inside the Studio's dependency tree, not in the site bundle or any request path. Revisit on each Sanity minor; don't `audit fix --force` (it downgrades Sanity).
